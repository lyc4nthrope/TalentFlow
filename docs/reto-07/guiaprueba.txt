¿Qué hacer si te llega a dar error de permisos en docker ps?
No hace falta tocar el host. Jenkins corre como root dentro de su contenedor (user: root en
docker-compose.yml), así que puede usar el socket tanto en Docker Desktop (Mac, el socket es de
root) como en Linux (el socket es root:docker y el GID del grupo docker cambia entre máquinas,
por eso usermod -aG docker jenkins no siempre alcanza).

No uses sudo chmod 666 /var/run/docker.sock: deja que cualquier proceso y usuario del equipo
controle Docker, y controlar Docker equivale a ser root en la máquina. Dejarlo así en un equipo
personal es un riesgo que no hace falta correr.

Root dentro del contenedor no agrega privilegio: quien tiene el socket ya controla el Docker del
host. Es aceptable para este entorno académico local; en producción se usarían agentes aparte.
